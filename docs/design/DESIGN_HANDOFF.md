Теперь выгрузи результат в виде, пригодном для вставки в проект.

Нужны четыре файла, каждый — отдельным блоком кода, с именем файла в первой
строке:

1. `tokens.css` — только переменные, светлая тема и блок тёмной темы.
2. `app.css` — полный файл.
3. `index.html` — полный файл.
4. `CHANGES.md` — отчёт.

Три требования к выдаче:

- **Файлы целиком.** Никаких «остальное без изменений», «…», «здесь как было».
  Код вставляют в проект как есть, любой пропуск ломает сборку.
- Если не помещается в один ответ — продолжай в следующих сообщениях в том же
  порядке, пока не закончишь. Не сокращай ради компактности.
- Код должен быть текстом в ответе, а не только внутри артефакта.

`CHANGES.md` должен содержать:

- новые классы и что они означают;
- удалённые классы;
- узлы, которые обёрнуты, переставлены или переименованы;
- **что требует правки в JavaScript** — словами, с указанием затронутого хука;
- новые ключи `data-i18n` списком;
- принятые допущения;
- посчитанный контраст для каждой пары токенов, обе темы.

И последнее, отдельным разделом в конце `CHANGES.md`:

**Самопроверка.** Пройди по критериям приёмки и напиши по каждому «выполнено»
или «нарушено, потому что…». Честно, без сглаживания:

1. В `app.css` нет литеральных цветов вне `tokens.css`.
2. В `index.html` нет `style=`, `onclick=`, `<style>`, внешних URL.
3. Все `id` и шесть классов состояния из `DOM_CONTRACT.md` на месте.
4. Существующие `data-i18n` сохранены, новые перечислены.
5. Контраст текста ≥ 4.5:1, элементов интерфейса ≥ 3:1, обе темы.
6. Смысл нигде не передаётся одним цветом.
7. Макет держится на 1440, 1024 и 390 px без горизонтальной прокрутки.
8. Бордо нигде не использовано как заливка; риск и статусы — только плашкой.

Если где-то отступил от задания — так и напиши. Расхождение, названное сейчас,
стоит дешевле, чем найденное при интеграции.
