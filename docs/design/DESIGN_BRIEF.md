# Procedra — бриф на редизайн интерфейса

Документ передаётся исполнителю целиком, вместе с `DOM_CONTRACT.md`.
Всё, что здесь написано, установлено чтением рабочего дерева, а не со слов.

---

## 1. Что за продукт

Procedra готовит черновики производственных рабочих инструкций и проводит их
через проверку человеком. Пользователь описывает задачу, продукт собирает
контекст из источников, генерирует инструкцию с пошаговой структурой, оценивает
её по десяти критериям, показывает происхождение каждого утверждения и ведёт
инструкцию через ревью, утверждение и исполнение с фиксацией доказательств.

Ключевое свойство: **продукт не претендует на правоту.** Он говорит, что
проверено, что требует локального подтверждения и какие вопросы задать эксперту.
Интерфейс должен это отражать: спокойно, без победных зелёных галочек и
геймификации.

## 2. Пользователь и условия

- Инженер по охране труда, технолог, начальник участка. Возраст 30–55.
- Работает на ноутбуке 1280–1920 px, иногда с планшета. Мобильный — вторичен,
  но обязан работать (drawer-навигация уже сделана).
- Русский интерфейс по умолчанию, есть переключение на английский.
- На экране много плотного текста: списки шагов, требования безопасности,
  источники, критерии. Это не дашборд с цифрами, это **рабочий документ**.
- Результат уносится с собой в PDF. Экран и PDF должны выглядеть одной семьёй.

## 3. Жёсткие технические ограничения

Нарушение любого из них означает, что код физически не заработает.

| Ограничение | Причина |
|---|---|
| Только vanilla HTML/CSS/JS | Нет сборщика, нет npm, нет фреймворка. Один `index.html`, один `app.css`, один `app.js` |
| **Никаких инлайн-стилей** — ни `<style>` в документе, ни `style="…"` на элементах | CSP: `style-src 'self'; style-src-attr 'none'` |
| **Никаких инлайн-скриптов и `onclick=`** | CSP: `script-src 'self'; script-src-attr 'none'` |
| **Никаких CDN, внешних шрифтов, внешних картинок** | CSP: `default-src 'self'; font-src 'self'` |
| Шрифты — только системные или самохостинг | `font-src 'self'`. Шрифт, который нельзя разместить рядом с приложением, использовать нельзя |
| Иконки — только SVG-файлы из `app/static/vendor/tabler-icons/` | Уже завендорены, лицензия приложена. Новые иконки — назвать имя из набора Tabler, не рисовать свои |
| Картинки: `img-src 'self' data: blob:` | Инлайн-SVG и data-URI можно, внешние URL нельзя |

## 4. Что нельзя ломать

Приложи `DOM_CONTRACT.md`. Коротко:

- **58 элементов ищутся по `id`** из JavaScript. Id обязан сохраниться.
- **6 классов состояния** переключаются из JS: `error`, `is-active`,
  `is-collapsed`, `is-mobile-open`, `mobile-menu-open`, `sidebar-is-collapsed`.
  Имена менять нельзя, оформление — можно любое.
- **Весь видимый текст приходит из JS-словаря** через атрибут `data-i18n`.
  В HTML элементы стоят **пустыми**: `<h2 data-i18n="formTitle"></h2>`.
  Не вписывай русский текст в разметку — он будет затёрт при первой отрисовке.
  Нужна новая надпись — добавь `data-i18n="новыйКлюч"` и перечисли новые ключи
  в отчёте, словарь заполню я.
- Язык переключается на лету. **Никаких фиксированных ширин** у кнопок, вкладок,
  подписей: русский текст в среднем на 15–25% длиннее английского.
- Доступность уже проверена и принята: `aria-expanded`, `aria-current`,
  возврат фокуса, закрытие по Escape, минимальная область нажатия 44 px,
  видимый фокус. Сохранить всё.

## 5. Что нужно на выходе

Ровно четыре файла. Никакого JavaScript.

1. **`tokens.css`** — только `:root` с переменными. Ничего кроме определений.
2. **`app.css`** — полная замена текущего файла (сейчас 1405 строк).
   Все значения — через переменные из `tokens.css`. Хардкод цвета, отступа,
   радиуса или тени в правилах не допускается.
3. **`index.html`** — полная замена (сейчас 300 строк), если структура меняется.
   Все `id`, классы-состояния и `data-i18n` из контракта на месте.
4. **`CHANGES.md`** — что изменилось и что от меня требуется:
   - новые классы и что они означают;
   - удалённые классы;
   - узлы, которые обёрнуты или переставлены;
   - **что требует правки в `app.js`** — словами, с указанием, какой именно
     хук затронут. Код на JS не пиши: в приложении 3077 строк логики, и любой
     присланный скрипт с ней столкнётся;
   - новые ключи `data-i18n` списком.

Комментарии в коде — на английском, по-минимуму, только к неочевидным решениям.

## 6. Экраны и компоненты

Одностраничное приложение. Боковая навигация переключает секции результата,
левая колонка формы остаётся на месте.

**Навигация (10 пунктов):** Генератор · Инструкции · Редактор · Выполнение ·
Проверки · Источники · Видео · История · Markdown · JSON · плюс «Свернуть».

**Основные блоки:**

- Шапка: бренд-марка, заголовок, контекст рабочего пространства, вход/выход,
  переключатель языка, кнопка мобильного меню.
- Панель ввода: ~12 полей — задача, уровень пользователя, тип инструкции,
  отраслевой профиль, операция, подразделение, оборудование, контекст,
  токен API, лимит источников. Плюс две сворачиваемые секции инструментов:
  видео (URL или файл, ключевые кадры, качество анализа) и документы (файл).
- Панель результата: заголовок, панель действий (улучшить, сохранить в историю,
  экспорт Markdown, экспорт PDF), тело результата.
- Два модальных окна: аутентификация и решение по маршруту согласования.
- Мобильный drawer с затемнением.

**Типы данных, под которые нужен визуальный язык:**

- Пошаговая инструкция: номер, действие, ожидаемый результат, примечание по
  безопасности, метод проверки, типовые ошибки.
- Оценка: десять критериев, у каждого балл, сильные стороны и замечания.
- Уровень риска: `low` / `medium` / `high` / `critical`.
- Источники: тип документа, причина попадания в контекст, публичный или локальный.
- Происхождение утверждения: подтверждено / требует локальной проверки / гипотеза.
- Статусы маршрута: черновик, на ревью, утверждено, отклонено, в исполнении.

## 7. Визуальный язык

Ориентир — Apple. Не «скруглить углы и добавить блюр», а конкретно:

- **Плоскостей мало.** Одна поверхность контента на нейтральном фоне. Карточка
  внутри карточки внутри карточки — запрещено.
- **Разделяет пустота, а не линии.** Границы — волосяные, 1 px, низкий контраст,
  и только там, где пустоты не хватает.
- **Тени почти нет.** Одна мягкая тень на всплывающих слоях (модальные окна,
  drawer). Панели контента — без тени.
- **Иерархия строится размером и весом, а не цветом.** Цветом выделяется
  действие и только оно.
- **Один акцент.** Основное действие на секции — ровно одно, и оно
  единственное окрашенное. Бордовая нота не конкурирует с ним: она про
  навигацию и ссылки, не про действие.
- **Типографика несёт нагрузку.** 4–5 размеров, не больше. Крупный спокойный
  заголовок, плотный читаемый текст, приглушённые подписи.
- **Ритм по сетке 4 px.** Все отступы кратны 4, основной шаг 8.
- **Движение служебное.** 150–200 ms, ease-out, только смена состояния и
  появление слоёв. Никаких эффектов ради эффекта. Обязательно
  `@media (prefers-reduced-motion: reduce)`.
- **Плотность выше, чем в потребительском приложении.** Это рабочий инструмент:
  инженер должен видеть шаг целиком, не прокручивая.

**Шрифт:** системный стек, без загрузки файлов —
`-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI Variable Text", "Segoe UI", Inter, system-ui, sans-serif`.
На macOS это San Francisco, то есть ровно тот ориентир, бесплатно и без запроса
к сети. Фирменный `Oxanium` остаётся **только** в логотипе-начертании, в
интерфейсном тексте не используется.

## 8. Палитра

тёплым подтоном, действие — почти чёрное, бордо работает как единственная
брендовая нота. Значения ниже — стартовые, посчитанные по контрасту; уточнять
их можно, ломать роли — нет.

### Ограничение, которое обязательно к исполнению

Бордо `#7A2E3C` и `critical` `#A8201A` **почти неразличимы по светлоте**:
контраст между ними 1.26 в светлой теме и 1.07 в тёмной. Оттенком эту пару
развести нельзя — бордо перестанет быть бордо. Поэтому разводим ролью и формой:

1. **Бордо никогда не заливка.** Только текст, тонкая линия, подчёркивание,
   кольцо фокуса, полоса у активного пункта навигации.
2. **Риск и статус — всегда заливная плашка** с фоном из таблицы выше.
   Никогда просто цветной текст.
3. **Зоны не пересекаются.** Бордо живёт в шапке, навигации и ссылках. Риск и
   статусы живут в панели результата, карточках оценки и бейджах инструкции.
   Если элемент оказался и там и там — цвет снимается, остаётся текст.
4. **Уровень риска всегда подписан словом.** Цвет — усиление, не носитель смысла.

Если этот набор правил нарушить, пользователь перестанет отличать «кнопка» от
«критический риск». В продукте про промышленную безопасность цена такой ошибки
выше, чем красивая картинка.

### Что ещё нужно затокенизировать

Кроме перечисленного выше — пары «фон + текст» на:

- три уровня доверия к утверждению: подтверждено / требует локальной проверки / гипотеза;
- пять статусов маршрута: черновик, на ревью, утверждено, отклонено, в исполнении;
- два типа источника: публичный и локальный.

Переиспользуй семантические цвета из таблиц выше, не вводи новые оттенки.
Утверждено и «подтверждено» берут `low`, отклонено берёт `critical`, черновик и
«гипотеза» — нейтральный серый, не цветной. Чем меньше в палитре оттенков, тем
надёжнее пользователь их различает.

## 9. Тёмная тема

Нужна, через `@media (prefers-color-scheme: dark)` и переопределение токенов —
не второй набор правил. Сейчас в приложении жёстко стоит `color-scheme: light`.
Тёмная тема — не инверсия: в тёмном режиме поверхность светлее фона, а не наоборот,
и акцент поднимается по светлоте, чтобы держать контраст.

## 10. Доступность — порог, а не пожелание

- Контраст текста ≥ 4.5:1, крупного текста и элементов интерфейса ≥ 3:1.
  **В обеих темах.** Приложи посчитанные значения для каждой пары токенов.
- Смысл никогда не передаётся одним цветом. Уровень риска — цвет **плюс** текст.
- Видимый фокус на всём, что фокусируется.
- Область нажатия ≥ 44 px.

## 11. Чего не делать

- Не переписывать на React, Tailwind, любой CSS-фреймворк.
- Не добавлять зависимости, шрифты по сети, иконочные шрифты.
- Не присылать JavaScript.
- Не вписывать текст в HTML в обход `data-i18n`.
- Не переименовывать `id` и классы состояния.
- Не рисовать градиенты, стеклянные панели, неон, скруглении больше 12 px,
  крупные тени, анимированные фоны.
- Не изобретать иконки — только имена из набора Tabler.

## 12. Критерии приёмки

Присланное принимается, если:

1. `app.css` не содержит ни одного литерального цвета вне `tokens.css`.
2. В `index.html` нет `style=`, нет `onclick=`, нет `<style>`, нет внешних URL.
3. Все `id` и шесть классов состояния из `DOM_CONTRACT.md` присутствуют.
4. Все существующие `data-i18n` на месте, новые перечислены в `CHANGES.md`.
5. Обе темы посчитаны по контрасту, значения приложены.
6. `CHANGES.md` называет каждую точку, где потребуется правка `app.js`.
7. Макет держится на 1440, 1024 и 390 px без горизонтальной прокрутки.
