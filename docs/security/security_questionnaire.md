# Ответы на типовой опросник

Формат: вопрос — ответ — где проверить. Столбец «где проверить» позволяет не
верить на слово: это команда, файл или эндпоинт работающей установки.

## Аутентификация и доступ

| Вопрос | Ответ | Где проверить |
|---|---|---|
| Как хранятся пароли | PBKDF2-HMAC-SHA256, 210 000 итераций, индивидуальная соль | `app/storage/auth_store.py` |
| Минимальная длина пароля | Не менее 12 символов в production; сервис не стартует при меньшем значении | `AUTH_MIN_PASSWORD_LENGTH` |
| Возможна ли самостоятельная регистрация | В production отключена, сервис не стартует при включённой. Доступ по приглашению | `AUTH_PUBLIC_REGISTRATION_ENABLED` |
| Может ли пользователь назначить себе роль | Нет, в production запрещено на уровне запуска | `AUTH_ALLOW_ROLE_SELF_ASSIGNMENT` |
| Защита от подбора | Блокировка учётной записи после N неудач на заданное время плюс отдельный лимит частоты на эндпоинты аутентификации. Попытки во время блокировки её не снимают и не продлевают | `AUTH_MAX_FAILED_ATTEMPTS`, `AUTH_LOCKOUT_SECONDS`, `AUTH_RATE_LIMIT_*` |
| Как хранится токен сессии | Хешем, не значением | `app/storage/auth_store.py` |
| Срок жизни сессии | Настраивается: полный срок, срок простоя, число одновременных сессий | `AUTH_SESSION_*` |
| Разграничение прав | Шесть ролей, матрица прав, разграничение по организации и проекту на уровне схемы базы | `docs/authorization.md` |
| Единый вход, LDAP, Active Directory | Нет. См. `limits_and_absent_controls.md` | — |
| Двухфакторная аутентификация | Нет | — |

## Сеть и передача данных

| Вопрос | Ответ | Где проверить |
|---|---|---|
| Куда уходят данные предприятия | Только в языковую модель и только при её включении. Полный разбор — `data_flows.md` | `GET /ready/details` |
| Можно ли работать без интернета | Да. `LLM_ALLOW_EXTERNAL_CALLS=false` требует эндпоинт внутри контура, проверка в трёх слоях | `GET /ready/details` |
| Есть ли телеметрия или «звонок домой» | Нет | Исходящих обращений в коде два, оба описаны |
| Автоматические обновления | Нет. Обновление выполняет администратор | — |
| TLS | Терминирует обратный прокси предприятия. Сервис слушает loopback | `APP_BIND_HOST` |
| Заголовки безопасности | CSP `default-src 'self'`, HSTS в production, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy` | Ответ любого запроса |
| Внешние CDN, шрифты, аналитика | Не используются, запрещены политикой содержимого | Ответ `/` |

## Журналирование и аудит

| Вопрос | Ответ | Где проверить |
|---|---|---|
| Что пишется в журнал | Строгий список полей: время, идентификатор запроса, актор, организация, проект, метод, шаблон маршрута, длительность, статус, категория ошибки | `app/core/request_logging.py` |
| Попадают ли в журнал данные предприятия | Нет. Тела запросов, тексты инструкций, содержимое документов, адреса почты и пароли не пишутся | Отправить запрос с узнаваемой строкой и поискать её в журнале |
| Есть ли аудит действий | Да. Аудит-след с хеш-цепочкой: каждая запись содержит хеш предыдущей | `make db-verify` |
| Можно ли отредактировать аудит задним числом | Два слоя. Правка и удаление отклоняются триггерами базы; при их снятии расхождение ловит хеш-цепочка. Оба проверены воспроизводимым сценарием | `make db-verify`, `threat_model.md` |
| Можно ли подменить текст утверждённой версии | Обнаруживается. Каждая запись аудита несёт хеш инструкции на момент события, проверка сверяет хранимый текст с последним из них | `make db-verify` |
| Метрики и `/ready/details` | Требуют предъявленных учётных данных — токена или сессии — независимо от режима. Разрешённый анонимный доступ к остальному API их не открывает. Публичная панель метрик в production запрещена на уровне запуска | `METRICS_PUBLIC_ENABLED` |

## Хранение, копирование, удаление

| Вопрос | Ответ | Где проверить |
|---|---|---|
| Где лежат данные | SQLite на сервере плюс каталоги загрузок и кадров, разложенные по организациям | `DATABASE_PATH`, `uploads/`, `generated/` |
| Шифруются ли данные на диске | Продуктом — нет. Ожидается шифрование тома или диска средствами площадки | — |
| Резервное копирование | Команды на согласованном снимке базы и восстановления из него | `make db-backup`, `make db-restore` |
| Проверка целостности после восстановления | Да, включая проверку хеш-цепочек аудита | `make db-verify` |
| Хранение сессий и метрик | Просроченные сессии удаляются, метрики хранятся ограниченный срок | `AUTH_SESSION_RETENTION_SECONDS`, `METRICS_RETENTION_SECONDS` |
| Удаление инструкций и документов по требованию | Отдельной процедуры нет. См. `limits_and_absent_controls.md` | — |
| Очистка временных артефактов | Скрипт с предварительным планом и раздельными режимами просмотра и удаления | `make cleanup-plan`, `make cleanup-delete` |

## Развёртывание и эксплуатация

| Вопрос | Ответ | Где проверить |
|---|---|---|
| Как поставляется | Docker Compose либо запуск на хосте; Python 3.12 | `docker-compose.yml`, `Dockerfile` |
| Под каким пользователем работает | Не root: `uid=1000(appuser)`, оболочка `nologin`. `подтверждено` запуском собранного образа | `docker run --rm <образ> id` |
| Попадают ли внутренние документы в образ | Нет. `подтверждено` проверкой собранного образа: ни `.env`, ни внутренних файлов, ни `reports/`, ни `docs/research/` в нём нет | `.dockerignore` |
| Переживает ли контейнер перезапуск | Да, `подтверждено`: после `docker restart` healthcheck снова `healthy`, `/ready` отвечает 200 | `docker restart` |
| Что происходит при небезопасной конфигурации | Сервис отказывается стартовать и перечисляет причины. Это поведение по умолчанию: `DEPLOYMENT_MODE` без настройки равен `production` | Запуск без `.env` |
| Готовый шаблон настроек для стенда | Есть, с закрытой регистрацией, жёсткими лимитами и выключенным видеоканалом | `deploy/stand.env.example` |
| Проверка состояния | Публичные `/health` и `/ready`; подробности и метрики требуют токена | `GET /ready` |
| Зависимости | Закреплены по версиям; проверка на известные уязвимости при каждом изменении | `requirements.txt`, `.github/workflows/ci.yml` |
| Есть ли перечень компонентов (SBOM) | Да, CycloneDX 1.4 с идентификаторами Package URL. Формируется командой и публикуется как артефакт сборки; в репозитории не хранится намеренно — перечень устаревает в день изменения любой зависимости | `make sbom` |
| Покрывает ли перечень пакеты операционной системы | Нет, только Python-зависимости приложения и их транзитивные. Граница указана в самом отчёте. Для пакетов базового образа нужен сканер контейнеров, которого в проекте нет | `generated/sbom/sbom_report.md` |
| Тесты | Автоматический набор, прогон при каждом изменении. Текущее число выводит сама команда | `make test` |

## Продукт и ответственность

| Вопрос | Ответ |
|---|---|
| Может ли система утвердить инструкцию сама | Нет. Черновик имеет статус `ai_draft` и блокеры, которые снимает только человек |
| Кто отвечает за содержание инструкции | Специалист предприятия, утвердивший версию. Продукт готовит черновик и фиксирует, кто что утвердил |
| Заявляется ли соответствие ГОСТ или правилам охраны труда | Нет. Продукт **сверяет структуру** документа с перечнем требований и показывает, с какими именно. Соответствие устанавливает человек |
| Есть ли внедрения | На дату составления комплекта — нет |
