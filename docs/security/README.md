# Пакет для службы информационной безопасности

Комплект для специалиста по информационной безопасности предприятия, который
решает, допускать ли Procedra в контур. Документы написаны так, чтобы их можно
было приложить к служебной записке без пересказа.

| Документ | Отвечает на вопрос |
|---|---|
| [`threat_model.md`](threat_model.md) | Что защищаем, от кого, и что происходит при каждом сценарии |
| [`data_flows.md`](data_flows.md) | Что покидает периметр предприятия, при каких настройках, и что не покидает никогда |
| [`security_questionnaire.md`](security_questionnaire.md) | Типовой опросник: аутентификация, права, журналирование, резервные копии, обновление |
| [`limits_and_absent_controls.md`](limits_and_absent_controls.md) | Чего у продукта нет и что не проверялось |

## Как читать

Утверждения в этих документах трёх видов, и вид указан явно.

**Подтверждено** — проверяется в коде и покрыто тестом либо воспроизводится
командой, которая приведена рядом. Такое утверждение можно проверить, не веря
на слово.

**Требует уточнения** — зависит от того, как развёрнута конкретная установка.
Ответ даёт администратор предприятия, а не поставщик.

**Гипотеза** — не измерялось. Помечено, чтобы не путать с первым.

Отдельный документ `limits_and_absent_controls.md` перечисляет то, чего нет.
Он написан не для полноты картины, а потому что служба безопасности всё равно
это выяснит, и лучше прочитает у нас.

## Статус продукта

Procedra — рабочий программный продукт, не прошедший внешний аудит
безопасности, сертификацию и включение в реестр отечественного ПО. Внедрений на
производстве на дату составления комплекта нет.

Комплект не заменяет аудит и не даёт права на подключение к промышленной сети.
Он даёт службе безопасности материал, чтобы сформулировать замечания по пунктам
вместо отказа по причине неизвестности.
